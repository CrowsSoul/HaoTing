## 验收原文如何落实

原文：“每条问题须说明位置、偏差量、严重程度与整改建议；四十四项均须给出结果位置。”

| 条款 | 自动检查 | 评审时还需人工确认 |
|---|---|---|
| 位置 | 坐标或包围盒、明确坐标单位、面编号、三维图片及引用一致性 | 位置和选面是否真正对应缺陷；外部截图、STL 与模型是否同源同坐标系 |
| 偏差量 | 实测、阈值、单位齐全，偏差等于实测减阈值；冲突保留源值并列为待复核 | 检测算法、阈值和标准依据是否正确 |
| 严重程度 | 必须是 P0/P1/P2/P3，非法值不再默认为正常等级 | 分级是否符合项目评审口径 |
| 整改建议 | 有实际文字，排除“请注意检查”等占位内容；建议来源、目标参数明确展示 | 目标尺寸或结构动作是否可执行，是否破坏配合、性能和安规 |
| 44 项结果位置 | 目录由平台 catalog 生成，44 个独立条目；Word/PDF/HTML 可跳转；未执行、缺数据、失败和跳过分开记录 | 每个项目的实际执行范围是否满足本轮验收，跳过理由是否认可 |

数值目标与结构动作均可作为整改建议。未给 param_delta 时，不自动编造尺寸，而是给出需人工确认的提示。生成报告成功仅证明导出完成，不等于数据完整、检测准确或产品合格。

## 本轮发现并修复的不足

1. 旧版 Word 索引只有章节名，PDF 只有书签：现补齐 44 个内部跳转链接，并验证目标存在。
2. 旧版没有独立验收台账：现每份归档包含 acceptance.json，逐条标明四要素是否齐全、44 项结果位置及待补事项；增加 audit 命令。
3. 旧版仅检查 deviation 存在，可能遗漏实测/阈值缺失：现同时检查实测、阈值、偏差及单位。
4. 旧版可能接受“请注意检查”之类占位建议：现列为待补充，不允许严格生成。
5. 旧版 status=ok 但未提供 finding_count 可能显示无问题：现改为执行状态待确认。
6. 旧版只有文件目录校验，未验证下载 ZIP 内容：现同时检查 ZIP 内成员及其哈希。
7. 旧版 M8 测试需单独运行：现通过 tests/test_m8_report.py 接入团队统一测试命令。
8. 图片曾仅按文件名归档：现保存模型哈希、问题 ID、面编号、坐标和图片来源。外部截图内容由提交者确认，不自动推断真实性。

## 已完成验证

统一命令 python -m unittest discover -s tests 共运行 100 项测试，99 项通过，1 项跳过，无失败。其中 74 项来自底座，26 项为 M8 回归测试。

M8 新增的 44 项合成格式测试，为每个检查项构造一条格式记录，验证三种报告、44 个 Word 跳转、44 个 PDF 跳转及书签、验收清单、图片追溯和原始数据不被修改。该数据仅验证报告模块的承载能力，不是检测器评测结果，也没有作为生产样张交付。

随包样张分别使用 board_a 开发数据，以及原压缩包自带 plate_holes 的 NX 几何快照与 STL。本地底座仅有 3 个参考检测器，样张中的 41 项未执行只描述这份本地底座；团队 GitHub 仓库已合入其他模块，不能据此推断团队仓库的实际完成进度。
