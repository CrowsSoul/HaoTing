# 标注集怎么标，评测怎么看

「DFM 准确率 ≥ 90%」这句话，只有在有标准答案、有匹配规则、有算分方式的时候才成立。
这份文档就是那三样东西。

---

## 一、标注集长什么样

一个模型一个文件，`mockdata/labels/<模型名>.labels.json`：

```jsonc
{
  "schema_version": "1.0.0",
  "model_id": "board_a",
  "annotator": "张三",
  "created_at": "2026-10-22",
  "labels": [
    {
      "label_id": "L001",
      "check_item_id": "DFM-31",
      "expected": "defect",          // defect=该报，ok=不该报
      "part_refs": ["P01"],
      "location": [10.0, 10.0, 6.0], // 缺陷位置 mm
      "tolerance_mm": 2.0,           // 位置容差
      "face_ids": ["F40181"],        // 可选，有的话优先按面匹配
      "note": "Ø3.7 非标孔"
    }
  ]
}
```

两种标注，缺一不可：

| `expected` | 含义 | 用来算 |
|---|---|---|
| `defect` | 这里**应该**报出来 | 召回（漏没漏） |
| `ok` | 这里**不该**报 | 误报（有没有瞎报） |

**只标正样本的后果**：一个「见谁都报」的检查器召回 100%，但工程师会被淹没。
负样本是唯一能压住这种刷分的东西。

## 二、匹配规则（`nxrp/eval/match.py`）

一条预测算命中，必须同时满足：

1. **检查项相同** —— DFM-31 不能顶 DFM-32；
2. **零件有交集** —— 至少落在同一个零件上；
3. **位置对得上** —— 坐标距离 ≤ `tolerance_mm`；有 `face_ids` 时优先按面匹配；
4. **一对一** —— 一条标注只能被一条预测命中，多余的算误报。

落在 `expected: "ok"` 位置附近的预测，直接记一次误报。

---

## 三、怎么算分

| 指标 | 算法 | 看什么 |
|---|---|---|
| 精确率 P | TP / (TP + FP) | 报出来的有多少是真的 |
| 召回 R | TP / (TP + FN) | 该报的有多少报出来了 |
| F1 | 2PR / (P+R) | 两者的折中 |
| **macro-F1** | 逐检查项 F1 的平均 | 合同「≥90%」对应这一条 |
| 误报率 | FP / (TP + FP) | 甲方最敏感，建议 ≤ 5% |
| 高危项召回 | 只统计 L3 检查项 | 建议 ≥ 95% |

两个细节容易踩：

- **该报却一条没报** → F1 记 0，不会因为「精确率无定义」而漏掉；
- **报了但没标注** → 记「未计分」，列在报告里，不混进 P/R。

## 四、跑一次

```powershell
python -m nxdrp check mockdata/models/board_a.model.json -o findings.json
python -m nxdrp eval findings.json -l mockdata/labels/board_a.labels.json
```

输出三块：逐检查项的表、整体指标、未计分项。

```powershell
python -m nxdrp eval findings.json -l labels.json --radius 3.0 -o eval.json
```

- `--radius`：位置容差，默认 2 mm；
- `--no-high-risk`：不单独统计 L3 召回。

## 五、标多少才够

合同附件 5 只承诺「每项至少 1 个样例」。**1 个样例算不出 F1**，只能算命没命中。

建议口径（写进启动会纪要）：

| 项 | 数量 | 说明 |
|---|---|---|
| 每检查项正样本 | ≥ 5 个 | 至少覆盖 2 种不同零件 |
| 每检查项负样本 | ≥ 2 个 | 「看起来像但确实没问题」的位置 |
| 总计 | ≥ 38 × 7 ≈ 266 条 | 一期 34 项 ≈ 238 条 |

标注的人必须是**懂工艺的工程师**，不能拿 checker 的输出反标——那样只会得到 100 分
和一个没用的检查器。`mockdata/labels/board_a.labels.json` 是**格式样例**，
由参考实现的输出自动生成，只能看格式，不能当基准。

---

## 六、这套东西怎么用

1. **写 checker 之前**：先把这一项的样例和负样本翻出来，看清「什么样算有问题」；
2. **写完第一版**：跑 eval，看 F1 和误报率，别只看「跑出来了」；
3. **调参之后**：再跑一次，确认没把别的项调坏（回归）；
4. **提交之前**：把 eval.json 一起放进去，别人能复现你的分数。
