## 1. 宋馨雨 · M2 智能安规（自研算法 + AutoCrear 对照）

**你要解决什么**

连接器里两个带电部件离得太近，电压高的时候会击穿空气打火。你要自己算出两种距离，再对照 IEC 60664-1 的限值判断合不合规：

- **电气间隙** = 两个导体之间**走直线**的最短距离（隔着空气）。
- **爬电距离** = 沿**绝缘件表面**走一圈的最短距离。沟槽、加强筋、倒角都会改变它。

**这是全项目唯一要科研攻关的地方**

电气间隙本质是两点距离，几何上有标准解法。爬电距离要在一张曲面上找最短路，还要按标准处理沟槽、筋、倒角的加减规则——没有现成库能直接用。所以 SAF-02 排在最难那一档。

**额外任务：把 AutoCrear 装起来**

不是拿它替代自研，而是让它先算一遍，给自研结果当对照基准。「精度不低于 AutoCrear」这条指标，有了它才证明得了。

装好之后第一件事：拿一个模型，让 AutoCrear 跑出一次爬电结果，存下来当基准样例。

| ID | 名称 | 你要做什么 |
|---|---|---|
| SAF-01 | 电气间隙 | 导体两两配对 → 求最短空间距离 → 查 IEC 限值表 → 判合规 |
| SAF-02 | 爬电距离 | 沿绝缘表面求最短路（表面切成网格，用图搜索走） |
| SAF-03 | 不合规归集 | 间隙或爬电任一项低于限值，就判这一处不合规 |
| SAF-04 | 量化建议 | 输出目标尺寸：加大到 X mm，或加绝缘筋让爬电达到 Y mm（二期） |

**先做哪件**

1. 把 IEC 60664-1 的限值表（额定电压 × 污染等级 × 材料组别 × 过电压类别）整理成 JSON，每条注明标准哪张表；
2. SAF-01 电气间隙先打通链路；
3. 同时把 AutoCrear 装上，跑出一份基准结果；
4. 再攻 SAF-02 爬电距离。

**关键节点**：第一周结束必须有一个能跑的爬电 v0.1，哪怕只支持简单沟槽。跑不出来就启动降级方案（先做 2D 截面投影 + 规则枚举），不要硬扛。

## 2. 于大淇 · M6A 钣金 DFM（8 项）

**你要解决什么**

钣金件折弯会裂、冲孔离板边太近会撕裂、翻边太高会拉断、槽太窄冲不出来。
这 8 项就是在出图之前，把「做不出来或者做出来很贵」的地方标出来。

**这 8 项几乎是同一个套路**

量一个尺寸 → 除以料厚 → 跟经验比值比。比如：

- 孔径 Ø2.0、料厚 1.5，孔径/料厚 = 1.33，小于最小冲孔比 1.5 → 冲不出来，报；
- 孔边到板边 5 mm，料厚 3，5 / 3 = 1.67，小于 2 → 太靠边，撕裂风险，报。

所以不要写 8 份复制粘贴：**先搭一套读表执行的代码**，把 8 行阈值填进
`rules/dfm_default.json` 的 DFM-19~26 段，然后 8 项就是 8 行数据。

| 组 | ID | 判什么 |
|---|---|---|
| 弯曲相关 | DFM-19 最小弯曲半径 / DFM-24 折弯与切口距离 / DFM-25 翻边高度 | 内 R ÷ 料厚、切口到折弯线距离 |
| 孔相关 | DFM-20 孔到边缘距离 / DFM-21 孔间距 / DFM-22 孔径与料厚比 | 孔径、孔距、边距 vs 料厚 |
| 槽与凸台 | DFM-23 槽的最小宽度 / DFM-26 冲压凸台高度 | 槽宽 ÷ 料厚、凸台高 ÷ 料厚 |

**从哪开始**

1. 先写 `rules/dfm_default.json` 里这 8 行的阈值表（每条注明依据：厂标还是经验值）；
2. 再写一套 `读表 → 取特征 → 比阈值 → 出 Finding` 的通用代码；
3. 然后一个文件、一个 checker，逐个跑通。

`nxdrp/checkers/examples/dfm31_tool_standard.py` 就是「读表判定」的完整范例，照着改。

**注意**：DFM-24 折弯与切口距离、DFM-26 冲压凸台高度是二期，先把另外 6 项做扎实。

## 3. 代世航 · M3 注塑 / 铸造 DFM

**你要解决什么**

塑料件设计出来，模具不一定做得出来：壁太薄注不满、壁厚不均会缩水、拔模角不够会拉伤、有倒扣模具拔不出来。这 11 项检查就是在开模之前把这些坑找出来——开一次模几十万，改设计不要钱。

**先分清几个词**

- **壁厚** = 塑料件的厚度。太薄注不满，太厚会缩水。
- **拔模角** = 零件从模具里拔出来需要的斜度，通常是 0.5°~1°。
- **倒扣** = 形状卡住模具拔不出来的结构，要额外做滑块，成本翻倍。
- **加强筋** = 为了强度加的薄片，根部太厚会缩水。

| 组 | ID | 怎么做 |
|---|---|---|
| 壁厚三件套 | DFM-08 / 09 / 10 | 算每个位置的壁厚，跟材料允许的最小值比；再看壁厚是否均匀 |
| 方向类 | DFM-13 拔模角 / DFM-14 倒扣 / DFM-17 多抽芯 | 面法向已经能取到，直接用 `from ...geom import draft_angle_deg` |
| 几何类 | DFM-11 加强筋 / DFM-12 模具壁厚 / DFM-15 凸台 | 先把特征认出来，再量尺寸 |
| 圆角类 | DFM-16 圆角半径 / DFM-18 尖角 | 看相邻两个面的夹角 |

**先把材料阈值表填进** `rules/dfm_default.json`（PC、PA66、PBT、POM……各材料的最小壁厚和拔模角都不一样），每条注明来源。然后按 DFM-08 → 09 → 16 → 13 的顺序推进，**11 项都要做完**——两周时间够，别自己先砍。

## 4. 汪琪俊 · M4 装配 DFM

**你要解决什么**

零件单看都没问题，装到一起就出事：两个件撞在一起（干涉）、孔对不上、扳手伸不进去。这 7 项检查就是在装配层面找这些毛病。

**这里的难点是误报**

软件说"干涉"，工程师打开一看是模型上有块碎面，根本不干涉。**甲方对误报极其敏感**——报三次假的，他就不信这个平台了。所以你的工作量有一半在"过滤掉不该报的"。

| ID | 名称 | 你要做什么 |
|---|---|---|
| DFM-01 | 干涉检测 | 两两求交，判断是真撞、临界、还是碎面造成的假象 |
| DFM-02 | 最小间隙 | 示例是包围盒粗筛（置信度 0.55）；精确测距用 ctx.nx.prefetch() + ctx.nx.distance() |
| DFM-03 / 04 | 孔对齐 / 孔槽对齐 | 拟合圆柱轴线，算同轴度偏差 |
| DFM-05 / 06 / 07 | 紧固件三项 | 可达性（扳手能不能伸进去）、间隙、螺纹啮合长度 |

**从 DFM-02 起步**：把包围盒粗筛换成 NX 精确测距，接着做 DFM-01 干涉甄别、再做孔对齐与紧固件三项，**7 项都要做完**。先验证装配结构（`occurrences` 和变换矩阵）对不对，对不上说明底座解析有问题，报给平台方，不要自己改数据格式。

**你要解决什么**

## 6. 张百瑞 · M6 钣金 + 机加工（20 项，最多）

**你要解决什么**

钣金件折弯会裂、冲孔离边太近会撕裂；机加工件孔太深钻头会断、圆角太小刀具进不去、孔径不是标准刀具还得定制。
这 20 项就是把这些"加工做不出来或者是做出来很贵"的地方标出来。

**好消息：这 20 项长得几乎一样**

绝大多数是同一个套路——**从模型里量一个值，跟一张表比**。比如：

- 孔径 Ø3.7 不在标准刀具系列 {3.5, 4.0} 里 → 要定制刀具 → 报
- 孔深 40、孔径 5，深径比 8 > 4 → 钻头易断 → 报

所以不要写 20 份复制粘贴。**先写一套读表执行的代码**，表放在 `rules/machining_rules.csv`（检查项、量什么、跟谁比、阈值来源），然后 20 项就是 20 行表数据。改阈值只改表。

| 组 | ID | 共同套路 |
|---|---|---|
| 钣金 | DFM-19 ~ DFM-26 | 特征尺寸 ÷ 料厚，跟经验比值比 |
| 机加工 | DFM-27 ~ DFM-38 | 特征尺寸 vs 标准刀具库 |

**先把这 20 项的"量什么、跟谁比、阈值哪来的"清单表交出来**。DFM-31/32 已有示例，照表驱动往下铺，**20 项都要做完**；表定了，代码是体力活。
**先做这两项**：DFM-31（对照刀具库）和 DFM-32（圆角种类数），`nxdrp/checkers/examples/` 里已经有完整参考实现。
**排到二期**：DFM-30 刀具可达性、DFM-37 窄通道，这两项要算空间遮挡，难度高一个量级。

## 8. 赵文哲 · M8 报告与知识库

**你要解决什么**

报告是甲方唯一能直接拿到手的东西。前面 44 个检查项做得再好，报告看不懂、说不出所以然，这个项目就是没交付。

**报告里每一条缺陷必须回答四个问题**

| 问题 | 用什么字段 |
|---|---|
| 在哪儿？ | 3D 定位图（`Finding.location` + `bbox`） |
| 差多少？ | 实测 `measured_value` / 阈值 `threshold_value` / 偏差 `deviation` |
| 多严重？ | `severity`（P0 阻断 / P1 严重 / P2 一般 / P3 提示） |
| 怎么改？ | `suggestion.text` + 目标尺寸 `param_delta` |

少任何一项，报告就变成"数据导出"，工程师不会照着改。

**先交一份样张**：把 `mockdata/models/board_a.model.json` 跑出来的结果渲染成一份能看的报告。样张出来之后再谈自动化，然后补建议模板库、归档和知识库。

**第二步**：建议模板库，按 `check_item_id` 索引，覆盖全部 44 项，给没有写建议的 checker 兜底。

## 协作规则（所有人）

1. **只改自己的目录。** `nxdrp/contracts/`、`pipeline.py`、`registry.py`、`checkers/base.py` 是公共的，要改先跟平台方说一声，别自己动。

3. **每个 checker 至少三个单测**：会报的、不会报的、正好卡在阈值上的。
4. **提交前跑** `python -m unittest discover -s tests`。
5. **每天早上 10 分钟对齐**：昨天做了什么、今天做什么、卡在哪。
6. **写完就讲一遍给别人听**，目的是你请假时别人能接手。
